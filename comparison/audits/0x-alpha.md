# Splash Critters — Audit of `0x-alpha`

## SPEC FIDELITY — SCORE 4/10
The shared sim is broad and real: chain bursts resolve in one tick via a queue (`sim.ts:260-311`), balloon kick slides tile-by-tile keeping fuse (`sim.ts:141-186`), power-ups are pre-rolled at map gen (`map.ts:99-116`), rising tide floods rings (`sim.ts:377-400`), pairwise-FFA Elo with K′=K/3 and K=64→32 (`elo.ts:43-62`, `config.ts:137-139`), matchmaker widens ±100→+50/10s→±400 (`matchmaker.ts:61-67`), room GC guards live matches (`rooms.ts:424-429` — `&& !room.match`, so it does NOT kill live matches), profanity filter (`queries.ts:20-28`), XP/levels/unlocks (`rooms.ts:565-580`), settings colorblind/reduced-shake ARE read by render (`game.ts:166,214`). But much only *looks* implemented: **revenge ducks lob from the death tile, they do NOT ride the border** — dead players get `p.moving = false` (`sim.ts:496-497`, comment says "ride duck along border" but nothing moves them; `fireRevengeLob` fires from `Math.round(me.x)`), **keybind remap is missing** from Settings (`settings.ts` has no remap; keys hardcoded `game.ts:115-118`), ranked forfeit/reconnect is absent (see findings), and the tutorial fights a random-wander bot, not the Easy AI (`tutorial.ts:104-113`). Combined with the showstopper below, the end-to-end journey the spec demands does not run online.

## SECURITY & ANTI-CHEAT — SCORE 5/10
Hygiene is good: `validateClientMsg` type-checks every branch, caps size at 2048 bytes and clamps input dirs (`net.ts:29,87-105`); rate limit is real at 60/s/conn (`net.ts:7-25`, `index.ts:83`); all SQL is parameterized (`queries.ts` throughout). **(d)** `hashToken` is never reached with a non-string — `hello` coerces any non-string token to `undefined` (`net.ts:41`), which I confirmed live (numeric/null/object tokens each just minted a fresh guest). **(f)** I booted the built server and fired 19 malformed/pre-auth frames (non-JSON, Infinity input, oversized token, `t:42`, arrays, pre-auth `start_match`/`queue_join`); the process stayed up (`/health` uptime kept climbing) despite there being **no `process.on('uncaughtException')` guard**. **(a) The seed probe is a real hole.** `round_start` ships `mapSeed` on the wire (`gameLoop.ts:63,80`; `protocol.ts:187-188`) but during matches the client uses only `castleGrid` (`game.ts:323`) — the generator is called client-side *only* in the offline tutorial (`tutorial.ts:1,61`). So the wire seed is **gratuitous**, and because `generateMap` is deterministic and public, contents are **fully derivable**: I reconstructed all 25 hidden power-ups (including the rare Boots) from a wire seed, `derived === server-side contents: true`. That defeats the spec's "never sent… unguessable, unhackable." No per-IP cap also lets guest+hello spam grow the `players` table unbounded (`index.ts:100-106`).

## CORRECTNESS — SCORE 3/10
1. **Showstopper: the server never sends `match_start`.** `grep` finds zero senders in `packages/server`; the loop only broadcasts `round_start` (`gameLoop.ts:77-92`), and `deps.sendToEntity` (which would carry the per-conn `yourEntityId`) is wired but **never called** (`index.ts:55`, `rooms.ts:441`). The client enters gameplay *only* on `match_start` (`main.ts:150-152`); `round_start`/`snapshot` reach `game.ts` handlers that early-return because `session` is still null. Online play never starts.
2. **Bots self-soak and Hard loses to Easy.** Server-faithful probe (30 duels, `autoKick=false` as `gameLoop.ts:68-70` sets): **Hard 0 / Easy 30**, round-end causes `selfSoaks=109, crossSoaks=0`. Bots never soak each other; the only deaths are the aggressive Hard bot killing itself (`bot.ts:142-159`, `escapeExistsAfterDrop` at `:350` fails to keep it alive). Violates "Bots never freeze or soak themselves" and "Hard reliably beats Easy."
3. **Ranked is unreachable and unrecoverable** (see finding 5).
4. Client ignores every `error` message — `main.ts`'s `net.on` switch has no `"error"` case — so `nickname_required`/`room_not_found` silently hang the UI.

## NETCODE — SCORE 3/10
Interpolation is genuine: `remotePos` renders remotes at `serverTime − interpDelayMs` (`prediction.ts:96`, `INTERP_DELAY_MS` read), sim is 30 Hz and snapshots gate to 15 Hz (`gameLoop.ts:148`), fuses render from snapshot tick + elapsed (`game.ts:223-225`). **But prediction is cosmetic, not rewind-replay:** `pendingInputs` is pushed in `addInput` (`prediction.ts:34-39`) and **never read**; `reconcile` only does exponential smoothing / snap-on-large-error (`prediction.ts:70-89`), and snapshots carry no last-processed-seq for the client to replay against (`types.ts:137-164`). The spec's "rewind-replay reconciliation" is absent. **Ping is fake:** `net.ping = 0` is never updated (`net.ts:10`), the server never sends `ping` (grep: none), and no HUD element shows ping. Clock offset is derived from snapshot ticks, not the required ping/pong-every-2s.

## CODE QUALITY — SCORE 7/10
Clean, modular, strict. Zero `any`/`@ts-ignore`; only 3 `as never`/`as unknown` (`soak.ts:15`, `rooms.ts:416`, `queries.ts:262`); `strict` + `noUncheckedIndexedAccess` on (`tsconfig.base.json`). `npm run typecheck` and `npm run build` both exit 0. The deterministic sim path is pure — no `Math.random`/`Date.now` inside `simulateTick`/`generateMap`; the only impurity is in convenience helpers `defaultMatchConfig` (`map.ts:138`) and `rngTheme` (`map.ts:143`), which the server/tests bypass by passing explicit seeds. Orchestration style matches the house pattern. Dead code drags it down: `pendingInputs`, `sendToEntity`, `cancelBotReplacement` (`rooms.ts:399`, never invoked), and the discarded reconnect `void active` (`index.ts:119`). (Per instructions, file length is not penalized.)

## TEST DEPTH — SCORE 6/10
The 26 tests genuinely assert behavior, not padding: identical seed → identical grid AND hidden contents (`sim.test.ts:23-29`), 3-balloon chain bursts in one tick (`sim.test.ts:106-145`, asserts `balloons.length` 3→0 on the single burst tick), splash stops at first castle (`sim.test.ts:72-104`), kick slides and stops at the wall (`sim2.test.ts:107-138`), same-tick double-soak = draw (`sim2.test.ts:175-201`), NaN/garbage input keeps state finite (`sim2.test.ts:95-103`), full-round determinism (`sim2.test.ts:223-242`), and exact Elo fixtures — duel 1016/984, K=64 first-10, FFA pairwise sum-to-zero and tie-sharing (`elo.test.ts:16-78`). Gaps: no integration/e2e test exists, so nothing catches the `match_start` gap; and the soak is weak and mis-wired — `npm run soak` runs `node packages/server/dist/soak.js` but the server tsconfig sets `"noEmit": true` (`packages/server/tsconfig.json`), so a normal build emits no `dist/` and the script fails with MODULE_NOT_FOUND (only `tsx` works). The soak also spawns just 2 bots for FFA (`soak.ts:10`) and asserts only completion — never "no self-soak" or "Hard wins," which is exactly why the bot inversion shipped unnoticed.

## TOP FINDINGS

1. **The server never emits `match_start`, so online matches never render.** Only `round_start`/`snapshot` are broadcast (`gameLoop.ts:77-92`); the client's sole entry into gameplay is the `match_start` handler (`main.ts:150-152`), and the `sendToEntity` path that would carry per-connection `yourEntityId` is wired but never called (`index.ts:55`, `rooms.ts:441`). Every casual/practice/ranked flow dead-ends on the lobby screen — the game is unplayable end-to-end.

2. **Bot AI is inverted and self-destructive.** Over 30 server-faithful duels, Hard won 0 and Easy won 30, with `selfSoaks=109, crossSoaks=0` — bots never soak each other and the Hard bot ends nearly every round by soaking itself (aggressive drop at `bot.ts:142-159`; `escapeExistsAfterDrop` at `bot.ts:350` does not actually keep it safe). This breaks both "Bots never soak themselves" and "Hard reliably beats Easy."

3. **The "unguessable" power-ups are trivially derivable.** `round_start` sends `mapSeed` (`gameLoop.ts:63,80`) even though matches only use `castleGrid` (`game.ts:323`), and the deterministic `generateMap` is public (`map.ts:99-116`); I reconstructed all hidden contents from a wire seed with `derived === server-side contents: true`. The seed is both gratuitous (unused by the in-match client) and a complete anti-cheat break.

4. **Client prediction is cosmetic, and ping is hardcoded.** `pendingInputs` is recorded but never replayed and snapshots carry no processed-seq, so `reconcile` only smooths toward authority (`prediction.ts:34-39,70-89`) — not the required rewind-replay. `net.ping` is a constant `0` (`net.ts:10`), the server never sends `ping`, and no HUD shows it.

5. **Ranked is unreachable and disconnects aren't handled; `npm run soak` is broken.** There is no nickname-setting UI (`set_nickname` is never sent by the client) yet the server gates ranked on `nickname_custom` (`index.ts:148-150`), and the client ignores the resulting `error`. Ranked disconnect has no forfeit and no reconnect — `hello` computes the active match then discards it with `void active` (`index.ts:119`) and `cancelBotReplacement` (`rooms.ts:399`) is never called. Separately, `server/tsconfig.json` sets `"noEmit": true`, so a normal build produces no `dist/soak.js` and the documented `npm run soak` fails with MODULE_NOT_FOUND.

## ONE-LINE VERDICT
A polished, strictly-typed, well-tested deterministic core wrapped in a product that cannot actually be played online — the server never tells the client a match started, the Hard bot loses to Easy by soaking itself, and the "unhackable" power-ups are derivable from a seed the client doesn't even use.

## Independent fact-checker verdict (second subagent)

All five findings independently verified through code inspection, live simulation, a working seed-derivation exploit, and a booted-and-fuzzed server.

1. **CONFIRMED.** The server never constructs `t:"match_start"` anywhere (grep across `packages/*/src` finds it only at the client handler `main.ts:150` and the type def `protocol.ts:177`). The client's sole gameplay mount, `enterGame` (`game.ts:63`), is called only from that handler (`main.ts:151-152`), and the round_start/snapshot net subscription is registered *inside* `enterGame`, so it never runs without match_start. `yourEntityId` (`protocol.ts:181`) is emitted by no server file, and `deps.sendToEntity` is defined (`gameLoop.ts:19`, `rooms.ts:441`, wired `index.ts:55-56`) but never invoked. Online play dead-ends at the lobby. Minor imprecision only: the loop also broadcasts `event`/`round_end`/`match_end`, not "only round_start/snapshot" — but match_start is genuinely never sent.

2. **CONFIRMED** (numbers marginally overstated). 50 best-of-3 Hard-vs-Easy matches through the real shared sim + `bot.ts`: **Easy won 45, Hard won 5**; soaks **self=177 (hardSelf=139, easySelf=38), cross=1, tide=0**. Bots essentially never soak each other, Hard self-soaks ~4× as often as Easy, so Easy dominates — the inverse of "Hard reliably beats Easy," and "bots never soak themselves" is broken. `escapeExistsAfterDrop` (`bot.ts:350`) demonstrably fails to keep the Hard bot safe. Nuance: Hard is not *literally* 0 wins and cross-soaks are not *literally* 0 (1/178), so the auditor's exact "Hard 0 / crossSoaks 0" is slightly overstated, but direction and magnitude hold.

3. **CONFIRMED.** `round_start` ships `mapSeed` (`gameLoop.ts:80`) plus `castleGrid`; the in-match `handleRoundStart` (`game.ts:322-334`) reads only `castleGrid` (line 323) and never touches `mapSeed`. `createSimState` (`sim.ts:24-25,57`) fills hidden power-ups from the public `generateMap(cfg)` (`map.ts:65-118`), and `makeSnapshot` (`sim.ts:547-576`) sends only `exposed`, never `hidden`. My exploit reproduced every hidden power-up from a wire seed: `derived === server-side contents: true` (14/14 tiles+types matched). Gratuitous and a full anti-cheat break.

4. **CONFIRMED.** `pendingInputs` is recorded (`prediction.ts:23,34-39`) but never read for replay; `reconcile` (`prediction.ts:70-89`) only hard-snaps at err>1.2 or lerps 0.18 toward authority — no rewind-replay. No processed-seq field exists anywhere in the protocol/snapshots. `net.ping = 0` (`net.ts:10`) is never updated, the server emits no `ping` (type only, `protocol.ts:259`), and no HUD reads it.

5. **CONFIRMED.** No nickname UI and the client never sends `set_nickname` (grep empty); the server gates `queue_join` on `nickname_custom` (`index.ts:148-150`), which defaults to 0 (`db.ts:18`) and flips to 1 only via `set_nickname`→`setNickname` (`queries.ts:81`); the client has no `t:"error"` handler, so `nickname_required` is silently swallowed → ranked is unreachable. `hello` discards the reconnect match via `void active` (`index.ts:119`); ranked disconnect just leaves the queue (`matchmaker.ts:127-128`) and `dropConn` only handles room matches — no forfeit/reconnect — and `cancelBotReplacement` (`rooms.ts:399`) is never called. `packages/server/tsconfig.json` sets `noEmit:true`, so `npm run build` produces no `dist/soak.js`; I ran the documented `npm run soak` and it failed with `MODULE_NOT_FOUND`.

SEED VERDICT: leaks real seed (client-derivable). `round_start.mapSeed` is the exact seed used to build the round's sim; the shipped shared `generateMap` reconstructs all hidden power-up contents from it (`derived === server-side contents: true`), while the in-match client never uses the seed itself.

CRASH VERDICT: none found. Built (`npm run build`) and booted the server (`npm start` → `tsx src/index.ts`) on :39217 with a temp DATA_DIR; a numeric-token hello returned a normal `welcome` (token coerced to `undefined` at `net.ts:41`), and 22 malformed frames (null/object/array tokens, non-JSON, array/number roots, Infinity inputs, oversized >2048B, pre-auth actions, `__proto__`, bad types) plus a 200-input flood all yielded `bad_msg` errors or were silently ignored.
